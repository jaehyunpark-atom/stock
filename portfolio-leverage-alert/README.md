# portfolio-leverage-alert

나스닥100(QQQ) 사상 최고가 대비 낙폭을 추적해서, QLD(-10/-15/-20/-25/-30/-35%)·
TQQQ(-45/-50/-55/-60/-65/-70/-75%, 닷컴버블급 전용 리저브) tier의 매수·익절·손절
시점을 카카오톡으로 알린다.

두 시스템으로 나뉘어 동작한다:

1. **이 repo의 GitHub Actions** (`.github/workflows/portfolio-leverage-alert.yml`)
   매일 05:30 KST에 `check_drawdown.py`를 실행해 yfinance로 QQQ/QLD/TQQQ 현재가와
   QQQ 사상 최고가를 정확히 계산하고, `state.json`에 결과를 커밋한다.

   각 tier는 `WAIT → PENDING → IN` (그리고 손절 시 `IN → COOLDOWN → WAIT`) 상태를
   독립적으로 오간다:
   - **WAIT → PENDING**: 낙폭이 그 tier에 도달.
   - **PENDING → IN (매수)**: 바로 사지 않고 반등 확인(최근 15거래일 저점 대비 +3%
     반등 또는 2거래일 연속 상승 마감)까지 기다렸다가 매수. 그 tier에 배정된 원화
     예산을 그 시점 QLD/TQQQ 가격으로 나눠 주식수를 계산해 `shares`에 고정 기록한다.
   - **IN → WAIT (익절)**: 낙폭이 진입 tier보다 10%p 개선되면(예: -20% 진입 →
     -10%까지 회복, -10% 진입 → 신고가) 진입 시 산 주식수 그대로 전량 매도.
   - **IN → COOLDOWN (손절, QLD만)**: 그 물량 자체의 진입가 대비 손익이 -20%
     이하로 빠지면 전량 매도. TQQQ는 애초에 깊은 tier에서만 진입하므로 손절이 없다.
   - **COOLDOWN → WAIT**: 낙폭이 그 tier 위로 완전히 회복해야만 재무장.
     (손절 직후 낙폭이 여전히 tier 아래면 바로 재매수하지 않는다 — 손절→즉시재진입
     →재손절이 반복돼 무의미해지는 걸 막기 위한 장치.)

   상품별 총 예산: QLD 1,320만원(6개 tier 균등분할, tier당 220만원),
   TQQQ 880만원(7개 tier 균등분할, tier당 약 125.7만원).
   (순자산의 10% 기준, 2026-09-24 순자산 2.2억 시점으로 산정 — 순자산이 유의미하게
   바뀌면 이 비율 기준으로 다시 계산할 것)

2. **Claude 클라우드 루틴** (claude.ai routines, 이 repo 밖에서 관리)
   매일 06:00 KST에 이 repo를 클론해 `state.json`의 `pending_alert`를 읽고, 값이
   있으면 카카오톡(PlayMCP)으로 전송한 뒤 `pending_alert`를 `null`로 되돌려 커밋한다.

계산(정확한 네트워크 접근이 필요)과 전송(카카오톡 MCP 접근이 필요)을 분리한 이유:
Claude 클라우드 루틴 실행 환경은 Bash의 직접 네트워크 호출이 막혀 있어 yfinance 같은
API를 안정적으로 쓸 수 없다. 대신 일반 네트워크 접근이 가능한 GitHub Actions에서
계산하고, 클라우드 루틴은 결과 파일만 읽어서 카카오톡 전송만 담당한다.

## 설계 배경

이 tier·손절·반등확인 구조는 QQQ 1999~2026년(닷컴버블 포함) 실데이터 백테스트로
검증했다. 손절 없이 "완전 회복까지 보유"하면 닷컴버블 재현 시 CAGR -5~0%대, 최대낙폭
-95%대까지 나오는 반면, 위 설계(tier+반등확인+QLD -20% 손절+익절)는 같은 조건에서
CAGR 약 7%, 닷컴버블 구간 오히려 소폭 플러스로 방어된다. 손절선을 완화(-30~-50%)하면
평상시(닷컴버블 제외) CAGR은 소폭 오르지만 닷컴급 이벤트 방어력은 크게 나빠지므로,
"닷컴급 사건이 다시 온다"에 무게를 두는 한 -20% 손절을 유지한다.
